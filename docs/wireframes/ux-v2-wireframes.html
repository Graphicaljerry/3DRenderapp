Read this before anything else

This redesign adds ~15 components and removes ~20. The simplification is real, but it is entirely contingent on the removals shipping in the same release as the additions. If the additions land and the removals slip, the app is measurably worse than it is today.

Nobody knows how to move the camera

The most-cited novice failure in 3D tools (Autodesk's own ViewCube study) is ending up "looking off into space where no data existed, or inside parts of the 3D model and/or upside down." Nothing in the app currently teaches pan or zoom.

One hint under the first model: "Drag to orbit · two fingers to pan · scroll to zoom · F to frame". ⌂ Home gets a permanent visible label, not just a glyph.

Submit — the load-bearing behaviour

const text = draft.trim(); if (!text) return;
setEntered(true);              // folds in the old enterFree()
setView("workspace");          // the route change
void send(text, forceMode);    // App.tsx:2618 — UNCHANGED

The string goes straight to the existing send(). It is never written into the workspace composer, never round-tripped. The first thing you see in the workspace is your own sentence as a bubble, already streaming. Nothing is re-typed.

The screen that "delays" you is what removes the wait

App.tsx:1034 reads if (!entered || sel) return; — so the ~11 MB OpenCascade WASM download doesn't begin until the gate is dismissed. Change it to if (sel) return; and the kernel compiles while you read the headline and type a sentence with three measurements in it. Net time-to-first-model goes down.

Taste call — labelled, not a finding

The background is a build plate in five CSS gradient layers: an isometric ±30° hairline grid masked to the bottom of the viewport, a low off-centre teal bloom, a cool counter-wash, a dark-mode-only key light, and FDM layer lines at 2.4% in the bottom 160px. Zero JS, zero network bytes, no backdrop-filter (the styles.css:344 ban stands).

No research says a printer-bed backdrop increases trust. It's defensible as design — on-brand, free, and not the generic AI-purple gradient — but it is a judgment. Not: aurora gradient (the AI tell), autoplay video (LCP killer), animated canvas (the app ships a real 3D viewport 200 ms later — a second fake one is a lie), or a photograph (this community has organised against beauty renders).

Print Bar v1 — ship only what exists

Content is dimensions · fits your bed · needs supports · Fit ⌄. Supports is half-backed — read this before drawing the tick. src/print/overhang.ts and overhangThresholdDeg compute an overhang ratio, triangle count and flagged area; there is no yes/no "needs supports" check anywhere in the codebase. A Print Bar that prints No supports ✓ is deriving a boolean from a ratio, and the threshold at which that flips is a product decision nobody has made yet. Make it, write it down, or print the ratio instead.

And fix the metric first. The Printability panel computes overhangFromHorizontal = PI - angleToUp and flags a face when that exceeds the threshold — which is inverted relative to both the overhang heatmap and physical reality (printability.ts:110-117 vs overhang.ts). The two surfaces disagree about which faces need support, and the panel is the one that is wrong.

The wall-vs-nozzle readout waits. "Walls 2.4 mm = 6× nozzle ✓" is computed from a setting that does not exist — PrinterDefaults is {bed, overhangThresholdDeg, name} and thinwalls.ts hardcodes 0.8 mm. Don't put unbuilt capability in the hero chrome.

Print time and filament estimates are not available and shouldn't be promised — they require actually slicing. src/lib/slicer.ts is a deep-link handoff only; that number comes from Bambu Studio or OrcaSlicer after the handoff.

Cross-cutting rules

  • Feedback lands where the action happened. Direct manipulation on the right no longer posts its explanation into the chat on the left (App.tsx:744-760 — and it fires once per device, so the second user of a shared machine gets nothing).
  • One popup, always. Five menus opt out of the app's own documented solo-menu invariant (Workspace.tsx:67-71). Two close only on onMouseLeave — impossible to dismiss on touch, on a product that ships for iPad.
  • Settings save on change. Today a stray backdrop click silently discards a freshly typed API key. Exception: secrets get an explicit Save and a dirty-close prompt.
  • Every AI result is forkable, not overwriting. Add Try again, differently so both candidates sit in History. "Regeneration overwrites the previous result" is a real failure mode today with no escape.

What sets this apart

Positioning

The only design tool where every dimension has a visible source, every clearance is calibrated to your printer, and the app proves the parts fit before anything is printed.

Not "AI that makes 3D models" — that's commoditised by Meshy and Tripo, and actively stigmatised by this audience (a Feb 2026 r/3Dprinting thread against AI models hit 2.4k upvotes; MakerWorld's Exclusive Program now excludes AI content outright). A fit-and-tolerance instrument that happens to use AI to draw.

Two corrections to the obvious plan

The Dimensions panel is L, not M — split it. CadParams = Record<string, number>, populated by regex. There is no unit, label, min/max or origin on any parameter; grep -rn provenance src/ returns zero hits. Phase A (S): render existing params + dims in one table, replacing the MeshStats / Selection Inspector / Set-size three-way overlap — ship this. Phase B (L): new prompt contract emitting {name, value, unit, role, source}, schema change, migration. Phase C: predicted printed size — needs nozzle and asymmetric hole/shaft compensation.

Making Fit permanent is a prompt-contract change, not a UI move. App.tsx:3017 is const fitLine = guided ? fitDirective(fit) : "". Fit is injected into guided prompts only. Making it permanent changes what the model is told on every precise build, and requires unpicking guided from four other behaviours it gates. Decide explicitly whether guided survives and what it still gates — three documents currently assume different answers.

Defects this section is quietly load-bearing on

The main export menu opts out of the app's own solo-menu invariant. ExportMenu uses a bare useState and never registers with useSoloMenu, so it stacks with other popups; it also has no Escape and no outside-click dismissal — it closes only on re-click, onMouseLeave, or picking an item (Workspace.tsx:2871-2875). Mouse-leave dismissal is unreachable on touch, on a product that ships for iPad.

“One .3mf per plate” fires N separate downloadBlob() calls in a loop with no zip and no progress, even though zipModelFiles() already exists and is used by the split path. Browsers throttle multi-file downloads, so a user can silently receive fewer files than plates (App.tsx:465-467). It also drops per-face MMU paint that the sibling “One project .3mf” preserves (exportClient.ts:96-126).

The plate bar's Export button is hard-coded disabled={false} — clickable with no geometry, where collectPlateParts() returns null and the click is a silent no-op (Workspace.tsx:523). The compact copy of the same menu in the Objects panel gates correctly.

The slicer rows promise a deep link that only exists in dev. openInSlicer skips the bambustudio:// / orcaslicer:// hand-off entirely unless import.meta.env.DEV, then silently downloads — while the menu still reads “sends the 3MF to the desktop app” (slicer.ts:25-38). It also ignores plates: a 3-plate layout hands off as one object.

The unit mismatch worth catching before this ships

The coupon adds its clearance to the hole diameter (makeCylinder((d + c) / 2, …)), but the number the user types is consumed as a per-side “snug” clearance. A user who measures a 0.30 mm diameter clearance and types it gets 0.30 mm per side — double what they measured. Either halve it on the way in or change what the coupon reports. Entering 0 is also accepted and silently collapses the whole ladder to 0.05 / 0.05 / 0.2 mm.

Deliberately deferred, and deliberately cut

⌘K command palette → v2. Every research note in the corpus warns against a palette before the IA is fixed — a palette that is the sole route to a feature is a junk drawer with a search box. Ship the IA, instrument it, then use real telemetry to decide what earns promotion.

The two-phase "Plan card" → cut, not deferred. A confirmation step between prompt and geometry. No research backs it, it doubles AI calls against the ≤3 target, and it delays first geometry against the TTFM target. Its actual job — catching wrong numbers cheaply — is better served by the Dimensions panel being editable after the first build, with no AI call.
